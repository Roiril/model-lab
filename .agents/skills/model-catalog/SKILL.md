# モデルを一覧に登録する

一覧の正本は `models/catalog-groups.json` と各モデルの `catalog.json`。Studio の `/api/models` はこの情報を表示する。寸法の正本は既存の `params.py` のまま。

SG92Rサーボと付属ホーンは `models/sg92r-photo/` が唯一の正本。2026-10-07にユーザーが確定し、旧 `sg92r` と `horn` を削除した。独立した実寸モデルや計測UIを再追加しない。寸法変更は正本の `params.py` と出典を記す `README.md` に反映する。正本の本体とホーンと配線は同じ一覧項目のパーツとして管理する。

新規作成や派生ではモデルの用途をソースと依頼から確認する。分類台帳にある用途と関連モデル群へ登録する。既存の群を優先する。異なる目的なら分類台帳へ固定IDと日本語名を追加する。名前から保管済みや不要と判定しない。

`models/<id>/catalog.json` に次を記録する。

```json
{
  "schemaVersion": 1,
  "title": "人が区別できる日本語名",
  "description": "何を作るモデルかが分かる短文",
  "categoryId": "分類台帳に存在する用途ID",
  "projectId": "同じ用途に属する関連モデル群ID",
  "tags": ["検索する対象名"],
  "status": "active"
}
```

形違いや寸法違いは同じ関連モデル群へまとめる。表示名に違いを含める。試し刷りと組み立て版は説明でも区別する。英語IDは検索と参照用に残す。フォルダの移動やIDの変更で分類しない。

`active` は通常のモデル。`reference` は参照用。`archived` は保管用。変更は依頼や保守の事実に基づける。検索と状態の絞り込みから保管用にも到達できることを確認する。

GLB やレーザー用データも台帳に登録する。Studio が表示できない形式には理由を表示する。見えるようにするためだけに空の `model.py` や `params.py` を作らない。

完了前に `node tools/catalog.js check` を実行する。JSONの欠損と分類の参照違いを直す。Studio で日本語の用途を検索する。派生は同じ群で区別できることを確認する。`# CATEGORY:` は古いモデルの互換用だけに使い、新規分類の正本にしない。

ユーザーのモデルと印刷成果物は一覧整理のために削除しない。追加した表示情報だけを明示的に stage する。表示できない形式を対応済みと報告しない。
