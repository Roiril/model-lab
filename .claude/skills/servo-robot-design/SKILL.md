# 1サーボ・ロボット設計ガイド（model-lab）

round-bot / square-bot（1サーボ・パン）と周辺部品（servo-test治具・sg92r/horn計測UI・eye・cat-ears/rabbit-ears）を作って得た知見の恒久版。新しいサーボ部品・嵌合部品・アクセサリを作るとき、まずこれを読む。

## 0. アーキテクチャ（最重要）

- **サーボが原点**。先に「サーボ実寸ソリッド」を置き、その周りに胴を生やす。モデルを作ってから穴を空けるのは必ず破綻する（肉厚・配線・ホーン逃げが後から入らない）。
- **機構は `lib/servo_core.py` に一元化**し、各キャラ/治具/アクセサリは import するだけ。外皮（round/square）は皮を差し替える「スキン」に徹する。
- **実物部品の寸法は単一の真実源（config クラス）に集約**：`SERVO`(SG92R) / `HORN` / `EYE`。ここを直せばマウント・受け・全モデルが追従する。
- **計測UIモデル**（`sg92r`, `horn`）＝ mm 入力 + `viewer/preview/*.js` のライブプレビュー。フロー：**実物をノギスで測る → UIに入れる → 形が合う → その値を servo_core の config に焼き込む**（2段階。UIは合わせ込み、config が本番の正）。

## 0.5 サーボを選ぶ（形より先に決まること）

- ⚠⚠ **「360°」と書かれたサーボは角度で止められない。** PWM のデューティで速度と向きを
  決める連続回転サーボで、角度指令を受け取らない。停止指令は「モーターを止める」であって
  「その角度を保つ」ではないので、**重力のかかる関節に使うと腕が落ちる**。可動域を広げる
  部品ではない。使えるのは縦軸まわりの旋回など、重力が押し返してこないところだけ。
- **電気の可動域（180°）は機械の可動域より狭いのが普通。** どの 180° を使うか設計時に決めて
  params に書く（servo-arm は肩 -25〜+155° / 肘 -30〜+150°。機械は 205° / 210° 回る）。
- **スプラインの山数 = ホーンの取り付け刻み。** 20 山なら 18° 刻みでしか差し替えられない。
  組むときはサーボを中央（90°）にしてから腕を窓の中央に当てて押す（ずれ最大 ±9°）。
- **定格トルクを params に書き、ビルドのたびにトルク収支を print する。**
  連続使用は定格の 1/3 が目安。肩トルクは `Σ(質量 × 関節軸からの水平距離)` で、
  **重心は体積重心で出す（頂点の平均だと肉抜きの多い側へ寄って過小評価する）**。
  実例: M5Stack 180°（1.8kg·cm @6V）で 100mm + 100mm の腕は、自重だけで枠の 76%。
  手先に載るのは 7g。関節間を 70mm にすると 42% / 25g。**長さは重さより効く**。

- **関節の太さはサーボの回転逃げ半径で決まる。ホーンを切っても縮まない。**
  頬板の半径は `max(ホーン長腕の半径, 背板内半径 + 背板厚)` で、背板内半径は
  `サーボ上部の回転逃げ半径 + 余裕` が効く（servo-arm では 17.1 → 18.6 → 21.6mm）。
  ホーンの長腕を 35 → 24mm に詰めても 22.8 → 21.6mm にしかならない。切らせる前に計算する。
- **土台の大きさは用途で決まる。** 卓上で自立させるなら前へ張り出させておもりを積む。
  他の機構へねじ止めするなら**支柱を覆う板＋ねじ穴だけ**でよく、張り出しもおもりも要らない
  （servo-arm は 76x112 → 44x52 に落ちた）。板の中心は関節ではなく**支柱**に合わせる。
  ⚠ ねじ穴が支柱の下に潜るとドライバーが入らない。穴の位置は自動で支柱の脇へ逃がす。

## 1. マウント設計の鉄則（ここで何度もハマった）

1. **上から挿入できる形にする。** 胴側に「スラストリング」を付けない——羽根が降りる経路を塞いでサーボが入らなくなる。頭はデッキ上面に直接乗せて回す（頭は軸に固定で回る＝胴とは“結合”しない。だから保持リング不要）。
2. **羽根はデッキ上面のポケットに着座**（重力で安定）。本体はデッキ穴を通って胴内に吊り下がる。羽根（幅広）はデッキ穴を通れないので上で止まる。
3. **頭の内部逃げは「回転対応の丸穴」**。頭は回るので、逃げが角穴だと回した瞬間に当たる。サーボのデッキ上プロファイルを丸で逃がす：
   - 羽根より上の**角型ケース**（数mm）＝**軸からの最遠角までの半径**で丸逃げ（`nub_r = hypot(BODY_L/2 + SHAFT_OFFSET, BODY_W/2)`）。軸はオフセットしているので意外に大きい。
   - **ギアカバー座**（大円柱）＝その径＋クリアランスの丸逃げ。
   - 軸（スプライン）＝中央。
   → この丸逃げを内包できるよう、頭の外形は十分大きく（round-bot は長腕クロスのため半径28に拡大した）。
4. **羽根より上のケースを忘れない。** 羽根の上に角型ケースが数mm突き出ていて、それを逃がさないと頭が浮く。

## 2. ホーン結合（致命的だった点）

5. **クロス受け溝は頭の底（floor）まで縦に貫通**させる。結合面の高さにしか溝が無いと、ホーン腕が溝の下の中実部に当たって**物理的に挿入できない**。腕が下から滑り上がって着座する縦チャネルにする（`cut_horn_coupling(..., floor_z=PLANE)`）。床は底面より少し下げて coplanar を回避。回転キーイングは溝幅で効く。
6. **非対称クロス対応**：長腕・短腕で長さも幅も別（`ARM_SPAN_X/Y`, `ARM_W_X/Y`）。実物は左右非対称なことがある（実測：横35×幅6.8 / たて17×幅3.6）。
7. **結合面の高さ**＝ギアカバー上面 ＋ (小円柱[スプライン]＋ホーンのスタック高 − 腕厚)。スタック高は「ギアカバー上面〜ホーン頂部」を実測（`HORN.STACK_H`）。
8. **ねじ止めの是非**：gentle pan なら**ねじレス（はめ込みキーイング＋摩擦）で十分**。頭は軸固定＋デッキで挟まれて落ちない。ねじ止めするなら**天面ザグリ**で短ねじにする（頭を貫通する長ねじは round で約15mm・square で約21mm＝非現実的）。`cut_horn_coupling(screw=True)` でザグリ＋シャンク穴が出る。

## 3. 配線逃げ

9. サーボの配線は**長手方向の端**から出る（ギアと反対側）。羽受け（フランジ座）にリボンが通る**小窪み**＋胴の底に**下開放スロット**を、**同じ側**に・**内部経由**で設ける。外壁を切るスリットにしない（見栄え＆「回る方向と配線方向が同じ」問題）。向き（±X）はユーザー指定に従う。
9.1 ⚠⚠ **配線の溝は「軸オフセットと反対の端」＝ -X に彫る**（2026-08-25 に実害）。
    `_servo_center_x()` が `-SHAFT_OFFSET` を返すので、本体は -X 側に長く、**線は -X 端から出る**。
    `cut_servo_mount` は長らく +X 端（ギア側）に 4mm 彫っており、**配線側には何の効果も無く、
    そのうえ +X のねじ下穴を丸ごと飲んでいた**（ねじが 1 本しか効かない）。
9.2 ⚠ **溝の深さは取付ねじの下穴に当たる手前で止める。** 本体面からねじ穴までは
    `SCREW_SPACING/2 - BODY_L/2 - SCREW_R` しかない（SG92R で約 2.6mm）。
    `cut_servo_mount` は自動で頭打ちにして実値を print する。**幅 6mm × 深さ 2.1mm** で
    3 芯リボン（実測 4.5 × 1.3mm）が通る。**溝が無いと、穴のクリアランス 0.3〜0.5mm では
    リボンを噛んで物理的に入らない**（座った状態では線はデッキより下だが、
    差し込む途中で必ず穴を通る。ここを見落としやすい）。

## 4. 単位の罠（事故った）

10. **model-lab はメートル単位**（1mm = 0.001）。Blender のメートル・ビューポートでは小物が極小に見えるため、手作業中に**うっかり拡大しがち**（実際カチューシャを59倍に拡大した事故）。実寸化するときは**信頼できる基準寸法**（バンド厚6mm／バンド幅など、耳に影響されない寸法）を測ってそこから均一スケール係数を出す。

## 5. boolean の落とし穴

11. **join（非多様体）後に EXACT boolean → 結果が空になる**。複数プリミティブは穴あけ前に **UNION で多様体化**してから掘る（`add_horn_dummy` / `add_eye_ball` 参照）。
12. カッター面がターゲットと**面一（coplanar）**だと boolean が不安定→**表面より0.5mm程度突き出す**。
13. ⚠⚠ **非多様体のまま次の boolean に入れると EXACT は「エラーを出さずに」壊れた結果を返す**（2026-08-25 servo-arm で実害）。従動側パーツ（16 本の non-manifold edge を持っていた）に駆動側を UNION したら、**サーボの羽根座とデッキ穴が塞がって 5159mm3 の材料が生えた**。単体で試すと正しく彫れるので原因が分からず遠回りした。
    - ⇒ **union / difference のたびに掃除する**（`remove_doubles(dist=1e-5)` → `dissolve_degenerate` → `recalc_face_normals`。models/servo-arm/model.py の `clean()` / `union()` / `cut()`）。掃除を挟むと non-manifold は 0 になり、同じ union が正しく通る
    - ⇒ 検証は **non-manifold 数だけでなく「サーボ実体ダミーとパーツの共通体積」**を測る。0 でなければ入るはずの部品が入らない
14. **長円・角丸を「箱＋円柱の UNION」で作らない。** 円柱が箱の面に**接する**（接線）ので長さ 0 のエッジが残り、上の事故の火種になる（`round_box_xy` も同型）。輪郭を多角形で作って押し出す（`prism_x`）方が確実に多様体。
15. **同じ座標を共有する板どうしの UNION（面一）も non-manifold の発生源。** 梁・支柱の端は相手の外面から **0.4mm 逃がす**（見た目は変わらない）。
16. boolean 後の**STL 法線が内向き**になり Blender workbench では「開いて見える」ことがあるが、メッシュは水密。viewer は `computeVertexNormals()` で再計算するため正しく表示される。**印刷可否は法線でなく水密性で判断**。

## 6. 検証の作法（[[feedback_modellab_visual_check]] と同旨）

17. ⚠ **`bmesh` を `transform()` した後は `normal_update()` を呼ぶ。**（2026-08-25 servo-arm）
    面法線は変換前のまま残るので、姿勢の回転を打ち消して印刷姿勢に戻したメッシュで
    オーバーハングを測ったら、**90° ずれた面を数えて 1240mm2 の宙吊り面があると誤報**した。
    計器の側が壊れていても数字は出るので気づけない。**答えが分かる入力（平らな板・
    既知の穴）で一度通してから使う**こと。
18. **印刷性は「45°を超える下向き面」ではなく「ほぼ水平（真下から 15°以内）な下向き面」で測る。**
    45°基準だと丸穴のアーチや円柱の下側が大量に引っかかるが、あれは自立する。
    水平に近い面だけ数えれば、橋渡しが要る場所（サーボ穴の天井・ホーン溝の天井）が残る。
19. **自前の Blender ヘッドレス確認レンダはカメラ角度・断面の取り方を間違えて誤判定しがち**（このプロジェクトで何度も別の面＝ドーム上面等を見て「壊れてる」と誤断した）。形の正否は次に寄せる：
    - **数値検証**：bbox 寸法、`bmesh` の non-manifold edge 数、パラメータ計算。
    - **ユーザーの viewer**（http://localhost:3000、法線再計算で正しく表示）での目視。
    - 撮るなら実績アングルのみ（真上 ortho／真横 ortho、look_at を bbox 中心へ）。断面の +Y ortho は空振り多数なので避ける。

## 6.5 組み立て可能性（設計と同時に確かめる）

20. ⚠⚠ **「組めるか」は部品を実際に動かして当たり判定で確かめる**（2026-08-25 servo-arm）。
    二枚の頬板でサーボを挟む関節は **軸方向からは絶対に入らない**（頬板がサーボ本体を
    通り抜けられない）。唯一の経路は「軸方向へ持ち上げてから、腕の伸びる向きに横から
    差し込み、降ろす」。そのために **頬板 ↔ サーボ本体の隙間 ≥ max(頬板厚, スプライン高)
    + 余裕** が要る。servo-arm は 0.8mm しか無く、**どの持ち上げ量でも組めなかった**
    （持ち上げないとピンに当たり、持ち上げるとサーボ本体に当たる）。5.5mm へ広げて解決。
    検証は「持ち上げ → 横入れ → 降ろし」の各段階で共通体積を測る（`assembly_arm.py` の型）。
21. **ドライバーが入る順番も設計のうち。** サーボの取付ねじはリンクを被せると頬板で
    塞がれる。ホーンのセンタービスだけは天面ザグリから最後に締められる ⇒
    「サーボ → ホーンをリンクへ → リンクを差す → センタービス」の順に固定される。
22. **サーボ実体ダミーは `join` でなく UNION で作る**（`add_servo_dummy` は修正済み）。
    非多様体のダミーを相手にした EXACT boolean は壊れた結果を返し、
    **上腕まるごと 33000mm3 を「共通部分」として報告**した（§5 の 13 と同じ事故）。
23. ダミーの配線スタブは剛体なので抜き差しの干渉判定で偽陽性になる（実物の線は曲がる）。
    干渉の bbox が y±2mm（スタブの幅）ならそれ。**配線は本体底から約 4mm の高さで
    尻尾側へ出る**ので、座った状態ではデッキより下を通って逃げられる。
23.1 ⚠ **「偽陽性」で片付けて終わらせない。** スタブが当たる事実そのものは
    「差し込む途中でリボンがデッキ穴を通る」という本物の設計要件を指している（→ 9.2）。
    判定は**2 本立て**にする: **A 剛体だけ**（本体・羽根・ギア座・軸。スタブを外して自分で組む）
    が 0 であること、**B 本体面に折り返したリボン**（4.5 × 1.6mm の板）が溝を通れること。
    A だけだと配線を見落とし、ダミーそのままだと必ず赤くなって何も分からない。
23.2 ⚠ **計器は答えの分かっている入力で 1 度通してから信じる。** A なら「サーボを Y へ 1mm
    ずらす」（クリアランスより大きいので必ず当たる）、B なら「リボンを 4mm 厚にする」
    （溝より厚いので必ず当たる）。0 が返ったら計器が死んでいる。
23.3 ⚠ **共通体積は「単体の部品」を相手に測る。UNION 済みの完成品を相手にすると数字がずれる**
    （ねじ穴まわりの肉を測ったら、単体 59% に対し完成品 65% と出た）。
    比率の判定に使うなら、その部品だけを作り直して測る。

## 7. 印刷向けの分割と向き

24. **パーツ分割**：胴／頭は別（間にサーボを挟む）。目は**接着ボール**（くぼみ径と同じ真球＋底を平らに、`add_eye_ball`）。耳はユーザーが Blender で手作り→別印刷。カチューシャはバンド＋耳を統合。
25. **印刷向き（サポート最小）**：胴は上下逆さ（デッキを下）／ドーム・頭はそのまま／アクセサリは面を寝かせて平ら（横置き）／目玉は底平面を下。
26. 出力前に**水密チェック**（non-manifold edge = 0 が理想。1〜数本ならスライサーが自動修復することが多い）。
26.1 **プリンタの設定は推測せず `exports/*.3mf` から読む。** Bambu Studio の 3mf は zip で、
    `Metadata/project_settings.config` に機種・造形範囲・層厚・サポートの有無・除外域が
    そのまま入っている（実測: X1C / 0.4 / 256x256x250 / 0.2mm / サポート OFF /
    `support_threshold_angle` 30° / 手前左 18x28mm は除外）。判定基準はここに合わせる。
26.2 **向きは決め打ちせず 6 通りの面接地を測って選ぶ。** 指標は「接地面積」「水平から
    30° 以内の下向き面」「外形」。servo-arm は 3 部品ともそのままの向きが最良で、
    回すと接地が 1/5 以下・垂れる面が 10 倍以上になった（`scratchpad/orient.py` の型）。
26.3 ⚠⚠ **「空中で始まる面」の判定を、真下や横のレイでやってはいけない。** 2 回とも間違えた:
    - **真下にレイ** … 10mm 上に浮いた板でも真下に土台があれば当たる。**見逃す**
    - **横にレイ** … 浮いた板でもレイは自分の側壁に当たる。穴の天井と区別できず**見逃す**
    正しいのは **「その層の高さで、領域の輪郭より少し外の点が肉の中か」**。肉があれば端が
    載る（橋渡し・張り出し）。無ければ空中。`closest_point_on_mesh` の法線の向きで内外を見る。
26.4 **校正は 2 つの形で。** 「浮いた板」（必ず検出されるべき）と「横向きの穴の天井」
    （検出されてはいけない）。両方通って初めて数字を信じる。

## 8. Blender 手作業との協調（MCP）

27. ユーザーが Blender で耳等を手作りし、こちらが統合する流れ：
    - band-only を読み込む（**オブジェクトモード必須**。編集モードだと ops の poll が context エラーになる）。
    - シーンのクリアは ops でなく **data API**（`for o in list(bpy.data.objects): bpy.data.objects.remove(o, do_unlink=True)`）が堅い。
    - 統合物は**信頼基準寸法で実寸化** → 横置き回転（厚みを Z へ）→ 中心化 → `bpy.ops.wm.stl_export(... export_selected_objects=True)` で `prints/<name>-assembled.stl` へ。
    - **形・位置はユーザーのを尊重**（こちらはサイズと向きだけ整える）。
    - 手作りジオメトリは .blend にしか残らない → ユーザーに保存を促す。

## 9. パイプライン保守

28. **新モデルを足したら `tools/print_export.py` の `MODELS` に追加**（eye/horn/cat-ears を入れ忘れて prints に出ない事故あり）。サイズ違いが要る部品（目：round⌀6.4/square⌀6.8）は別名で明示書き出し。
29. viewer：`params.py` の `# CATEGORY: 名前` でカテゴリ分け。mm入力モデルは params を mm で書き model.py で `*0.001`。数値入力欄は input 中に値を書き戻さない（書き戻すと小数点が打てなくなる）。

## 10. 定番コマンド

