# モデル依頼の共通条件

印刷して使うモデルの依頼に、毎回かかる条件。2026-10-10 制定（servo-lid-cube の依頼文を精査して抜き出した）。

## 使い方

- **優先順**: 依頼文 ＞ この共通条件 ＞ CLAUDE.md の一般ガイドライン。依頼文に書いていない項目は、ここの既定で進める
- **外すとき**: 依頼文に「共通条件の §4 ねじ禁止は外す」のように節と項目で書く
- **ここにも無い項目**は自分で決める。報告の「決めたこと」欄に、値・理由・変えるときの `params.py` の定数名を並べる。
  ユーザーに訊き返さない（グローバル規約）。決めた値が後から覆りやすいよう、必ず定数にしておく
- 依頼文の書き方（個別部のひな形）は末尾の §10

---

## 1. 寸法の出どころ

- 既製部品（サーボ・ホーン・スマホ・パイプなど）の寸法は、リポジトリ内の正本を **import して使う**。`params.py` に書き写さない
- 正本を探す順: 依頼文の指定 → `models/<部品名>*/params.py` と README → 無ければ公称値（データシート）を調べて正本を作る
  - SG92R とホーンの正本は `models/sg92r-photo/`。`lib/servo_core.py` の値は既存ロボット用で、正本として扱わない
- 正本の中の**仮値・推定値**（README やコメントに「仮」「推定」とあるもの）を作業の最初に一覧にする。
  その寸法に嵌め合う部分は、**確かめ用の小さな部品**（15 分程度で刷れる大きさ）を本体より先に出す
- 正本どうし・参考モデルどうしで値が食い違ったら、公称値を調べ直し、採った値と理由を報告する
- 参考モデル（3mf）を渡されたら `lib/read_3mf.py` で実績値を読む（CLAUDE.md「参考モデルを読む」）

## 2. 参考にしないもの

- 依頼文の「〇〇を参考にしない」は、その**形・機構・部品の分け方**にだけ効く
- 検証の仕組み（Studio の「物理検証」「組み立て」タブ、判定スクリプト、`lib/` の部品）は使ってよい。範囲を広げて解釈しない
  （2026-10-09、「住人の箱を参考にしない」を検証タブにまで広げ、結果が別ページにしか出なかった）

## 3. 印刷

### プリンタと材料

- Bambu Lab X1C、ノズル 0.4mm、層 0.2mm。造形範囲 256 × 256 × 250mm、手前左 18 × 28mm は除外域
- H2D で刷るときは依頼文に書く（`tools/plate_3mf.py --bed=h2d`）
- 材料は PLA が主。PETG でも組めること。嵌め合いは PLA で合わせ、PETG で固くなる箇所があれば報告する
- 全部品を 1 枚のプレートに収める。収まらなければ分け方と理由を書く

### 見える面をきれいに刷る

- **見える面の既定**: 組み上げて使っている状態で外から見える面と、可動部を動かしたときに見える面
- 見える面にはサポートを付けない。造形姿勢は、見える面がベッドに接するか上を向く向きを選ぶ
- サポートは見えない面にだけ使ってよい。使ったら部品ごとに場所と理由を書く
- 向きは決め打ちしない。面接地の候補を並べ、接地面積と水平に近い下向き面で選ぶ（servo-robot-design §7 26.2）
- 横穴は涙形にするか天井を平らに切る。橋渡しは 10mm 以内で、見えない面だけ

### 刷っている最中に揺れない

- 立てて刷る細い部分（柱・ピン・薄い壁）は、高さを太さの 5 倍以内にする。超えるなら寝かせるか、根元を太くするかリブを付ける
- 接地面が小さく背の高い部品は、倒れない向きに変える

### 刷り上がりがしならない・ガタつかない

- 肉厚の既定: 外装の壁 2mm 以上、力を受ける壁・腕・軸受け 3mm 以上。どこでも 1.2mm を下回らない
- 隙間の既定は CLAUDE.md の表（はめ込み片側 0.2〜0.4mm、ゆるい片側 0.5〜0.8mm）。回る軸は片側 0.2mm から始める
- ベッドに接する縁で嵌め合う部品は、最初の層の膨らみぶん 0.3mm 面取りする
- スナップ・圧入・曲げて入れる部品は、層に沿ってしなる向きで刷る（層をまたいで曲げると割れる）

### メッシュ

- 非多様体エッジ 0。boolean のたびに掃除する（servo-robot-design §5）
- 一体の部品は連結成分が1個であること。試片を複数並べたSTLは意図した個数を記録する。支持材なしの別部品は、各成分が印刷面に接地していることも確認する。閉じたメッシュでも空中に離れた部品は印刷できない。
- 凹んだ輪郭を n-gon の蓋で閉じない。数値の検証では見つからないので Studio で目で見る

## 4. 組み立て

- 使うのは印刷部品と、依頼文で挙げた既製部品だけ。結束バンド・接着剤・両面テープ・別に買うねじやナットは使わない
- 既製部品に付属するねじ（サーボの取付ねじなど）も、依頼文に書いていなければ使わない
- 工具なしで手で組めること
- 壊さずに分解できること（サーボの交換や角度の合わせ直しのため）
- 組む順番で、後から入れる部品の通り道と、指の入る隙間が残っていること
- 抜け止めは圧入・スナップ・バヨネット・落とし込みなど、印刷部品の形で作る

## 5. 動く部品がある場合

- 設計の作法は `.claude/skills/servo-robot-design` を先に読む。機構の決め方・印刷部品だけの継ぎ手・検証の型・
  刷る 3mf の作り方は共通スキル `printable-mechanism-design`（`~/.claude/skills/` / `~/.agents/skills/`）
- 依頼文に動きの指定が無ければ、動く範囲と速さを決めて `params.py` に書き、「決めたこと」欄で報告する
- トルク: 必要トルクは停動トルクの 1/3 以下。重心は頂点の平均ではなく体積で出す
- 使う角度はサーボの電気の可動域（180°）の中で決める。ホーンは山の刻み（SG92R は 20 山で 18°）でしか付け直せないので、
  組むときの合わせ方（中央の 90° でホーンを付け、端の角度はソフトで決める等）を手順に書く
- 端で当たる動きは、当たる速さを出す。強ければ速度を落とす動かし方（時間・ゆっくり始めて止める）を指定する
- 電源を切ったときにどうなるか（自重で動くか、止まったままか）を報告する
- 配線は可動部に挟まれない経路を通し、コネクタごと外へ出せる大きさの出口を付ける（SG92R の 3 ピンは 8 × 4mm で通った）

## 6. 検証と合格の基準

**どの判定も、先に計器を校正する。** 「必ず引っかかる形」と「引っかからない形」を同じ手順で通し、
両方が期待どおりのときだけ本番の数字を信じる。校正の結果も報告に載せる。

| 何を | 合格の基準 | 参照実装 |
|---|---|---|
| 形 | 外形が依頼の範囲内。非多様体エッジ 0 | `/print-check` |
| 動く範囲の干渉 | 全範囲を 2.5° 刻み以下で、部品どうしの共通体積 0 | `models/servo-lid-cube/verify.py` |
| 組み立ての経路 | 各工程で部品を入れる経路がある。当たってよいのは設計した圧入とスナップだけで、量（mm）とひずみ（%）を出す。ひずみは PLA で 2% 以下 | 同上 |
| 刷れるか | Bambu Studio の CLI で部品ごとにスライスし、支えの無い押し出しが見える面に無い。サポートなしで刷る部品にサポートが要らない | `models/servo-lid-cube/slice_check.py` |
| 動く力（動く場合） | §5 のトルクの基準。動く時間と、端で当たる速さを出す | `models/servo-lid-cube/simulate.py` |

- 案内・軸受けなどの剛体接触も、実メッシュの共通体積を測る。接触する部品の組を丸ごと除外したり、未測定の体積を0と記録したりしない。数値誤差の許容値は校正で先に固定し、実測した干渉を通すために広げない。
- 圧入・スナップの許可は接触位置と変形量に限定する。同じ部品の別の場所まで許可せず、必要な変形とPLAのひずみを併記する。
- 計算で確かめたことと、実物でしか確かめられないこと（仮値の寸法・摩擦・材料のばらつき）を分けて書く

## 7. 見せ方

- Studio を `http://localhost:3000/?model=<name>` で開いた状態で渡す（CLAUDE.md「ユーザーへの見せ方」）
- 動く部品か組み立て工程があるモデルは、Studio の「物理検証」「組み立て」タブに登録し、検証結果をそこから見られるようにする
  （`viewer/shared/workspace.mjs` の `WORKSPACE_PAGES`。実例は `viewer/lid-cube/`）

## 8. 渡すもの

- `prints/<name>/` に部品ごとの STL と、プレートに並べた 3mf（`tools/plate_3mf.py`。重なり・はみ出し・除外域の行を読んでから渡す）
- `models/<name>/README.md`
  - 部品表（印刷部品と既製部品）
  - 刷る向きと、サポートを使う箇所
  - 組み立て手順（どの向きに持って、何をどこへ入れるかを 1 工程 1 行）
  - 動く場合は初期角度の合わせ方と、動かし方（速さ）
  - ビルドと検証の流し方（コマンド）
- `models/<name>/catalog.json`（表示名と用途）を書き、`node tools/catalog.js check` を通す
- 印刷時間とフィラメント量（スライス結果から）
- 最初に刷る確かめ用の部品と、合わなかったときに変える `params.py` の定数名と刻み
- コミットして push する

### 報告に必ず入れる欄

- **要件ごとの結果**: 依頼文の要件と共通条件の §3〜§6 を 1 行ずつ
- **決めたこと**: 依頼文にも共通条件にも無く、自分で決めた値と理由
- **譲ったこと**: §9 の優先順で譲った要件と、その代わりに何を取ったか
- **実物で確かめること**: 刷ってから見るべき箇所と、その順番

## 9. 要件がぶつかったとき

依頼文に指定が無ければ、この順で優先する。

1. 組めること・動くこと
2. 見える面がきれいに刷れること
3. 依頼文の見た目（形・見えてよいもの）
4. 大きさと部品数の少なさ

## 10. 依頼文のひな形（個別部）

共通条件に無い項目と、共通条件から外す項目だけを書く。書かない欄は既定で進む。

```
〈作るもの〉を作ってほしい。

■ 使い道
〈何に使うか。置き場所・手で触るか・中に入れるもの〉

■ 使う既製部品と寸法の出どころ
〈部品名: models/<部品>/params.py〉

■ 見た目
〈外形の上限・形〉
〈外から見えてよいもの（継ぎ目・蝶番・配線口など）〉

■ 動き（動く部品があるとき）
〈どこが・どの範囲で・どれくらいの速さで動くか〉
〈途中の角度で止めるか〉
〈電源を切ったときどうあってほしいか〉

■ 中に入れるもの・配線
〈内側の空き・マイコンや電源の置き場所・配線の出口〉

■ 参考にするもの・しないもの
〈参考モデル（3mf）/ 参考にしない過去のモデル〉

■ 共通条件から変えること
〈例: §4 のサーボ付属ねじは使ってよい / §9 は見た目を最優先〉
```
