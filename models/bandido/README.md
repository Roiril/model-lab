# バンディド (Bandido) — トンネル札

協力ゲーム「バンディド」のカード（全 32 枚）を、テクスチャ付き 3D モデル（GLB）として
再構築したもの。アルゴ (algo)・海底探検 (deep-sea-adventure) と同じライン
（写真から抽出 → bpy でテクスチャ付き薄板メッシュ → GLB）。

白背景で 1 枚ずつ撮った実物写真からカード面を輪郭抽出・透視補正し、縦長 1:2 に正規化して
テクスチャに使う。角丸はメッシュ側（角丸長方形の外形）で切り、テクスチャは角スリバー
（紙の写り込み）を内側の色で充填して全面カード色にしてある。裏面は全カード共通の `ura`。

## パイプライン

```
gen_textures.py   生写真を Lab 彩度+暗部で分離 → 4隅で透視補正 → 縦長 1:2 に正規化
                  角スリバーを inpaint 充填した全面テクスチャ → exports/bandido/tex/*.png
                  角丸長方形アウトライン + 側面色 → exports/bandido/outlines.json
build_glb.py      bpy が JSON を読み、UV 付き角丸薄板メッシュを生成
                  表=面テクスチャ / 裏=共通 ura / 側面=地色ソリッド
                  → glb/<name>.glb（単体 32 枚） + bandido.glb（俯瞰 8x4）
                  テクスチャは JPEG(q90) で GLB 埋め込み（俯瞰 GLB ≈ 5.5MB）
render_preview.py 俯瞰 + 単体ヒーローを EEVEE でレンダ → _preview.png / _hero.png（確認用）
```

実行（model-lab ルートで）:

```bash
python models/bandido/gen_textures.py      # 生写真 → tex + outlines.json
./run.sh models/bandido/build_glb.py       # → glb/*.glb + bandido.glb
./run.sh models/bandido/render_preview.py  # 任意（確認用）
```

## 閲覧（model-lab ギャラリー）


## 構成（32 種 / デッキ 70 枚 + 共通裏）

| グループ | 種類 | 同梱枚数 | デッキ計 | 内容 |
|---|---|---|---|---|
| トンネル札 | 24 (g1〜g24) | 各 2 枚 | 48 | 木目地に黒いトンネル路 |
| 特殊札 | 7 (l1〜l7) | 各 3 枚 | 21 | 行き止まりに懐中電灯を持つ人物 |
| 開始札 | 1 (bandy) | 1 枚 | 1 | 牢の囚人 |
| 裏面（共通） | – (ura) | – | – | 全カードのボトム面に使用 |

- 単体 GLB は**種類ごと 1 つ**（32 個）。俯瞰 GLB `bandido.glb` は**実枚数 70 枚**を
  10×7 で並べる（追加分はメッシュ/マテリアルをリンク共有した複製 → 画像は重複排除）。

- カード寸法: **44 × 88 mm**（写真アスペクト実測 1:2）、角丸半径 ≈ 2.9mm、厚み 1.5mm（表示用）
- 単位はメートル（Unity 1 unit = 1m）。カード短辺 ≈ 0.044 unit。

## 入力（生写真）

`params.py` の `RAW_DIR`（既定 `C:/Users/kouga/Downloads/bandyd`）にある
`<name>.jpg` を読む（git 管理外・ユーザーの生写真）。ファイル名がカード名になる。
別の場所に置く場合は `RAW_DIR` を書き換える。

## 設計メモ

- **向きの統一**: カードは物理的に全て 1:2。横向き撮影（bandy 等）は**回転のみ**で縦長化し、
  引き延ばし（アスペクト変形）はしない。正確な 2.0 への補正は 2% 未満。
- **角丸**: テクスチャは角まで不透明（角スリバーを内側色で inpaint 充填）にし、
  実際の角丸はメッシュ外形で切る。テクスチャのアルファ半径と mesh 半径は物理一致。
- **側面色**: 各カードの縁から 20〜60px 内側の帯の中央値を採色（紙のにじみを避ける）。
- テクスチャは写真のため GLB へは JPEG(q90) 埋め込み。PNG 直だと俯瞰 GLB が 67MB になる。

## 既知の制限・TODO

- カード寸法は写真アスペクト（1:2）由来の推定。実物の公式寸法で採寸し直す余地あり。
- 抽出は minAreaRect（回転矩形）ベースで、強い遠近ゆがみは補正しない（ほぼ真上撮りを前提）。
- バンディドのデッキ構成（各札の枚数）は未反映。写真にある 32 面をそのまま 1 面ずつモデル化している。
