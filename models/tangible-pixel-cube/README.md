# 住人の箱 C4-3・タンジブル画素キューブ

外形は96 × 96 × 96mmです。天面の5 × 5枚の正方形（画素）が、SG92R 1台で−3〜+3mm上下します。画素が出ると最大99mmで、10cm以下に収まります。

どの画素がどれだけ動くかは、`patterns.py` の高さの表で決めます。表は5枚です。表に合わせて画素ごとのカムを生成し、カム25枚を刷ります。サーボ角で表を選びます。

天面を上にして置く専用です。画素は重力でカムに載ります。電源を切った後の位置は保証しません。指で押した入力は検出しません。

## 何ができるか

表は5枚で、サーボ角の昇順に並びます。90°が全部面一の「平ら」で、組み立てる角度でもあります。

| 表 | サーボ角 | 名前 | 動き |
|---|---:|---|---|
| 0 | 22° | wave | 斜めに進む波。±1mm |
| 1 | 56° | dip | 中央が−3mm。上下左右の隣が−1.5mm。斜めの隣が−1mm。外側が−0.5mm |
| 2 | 90° | flat | 全部0mm（組み立てる角度） |
| 3 | 124° | bump | 中央が+3mm。上下左右の隣が+1.5mm。斜めの隣が+1mm。外側が+0.5mm |
| 4 | 158° | corners | 四隅が+1.5mm。その隣が+0.5mm |

表1の高さです（mm。行が前後のY、列が左右のX）。

```
-0.5 -0.5 -0.5 -0.5 -0.5
-0.5 -1.0 -1.5 -1.0 -0.5
-0.5 -1.5 -3.0 -1.5 -0.5
-0.5 -1.0 -1.5 -1.0 -0.5
-0.5 -0.5 -0.5 -0.5 -0.5
```

サーボは連続して回るので、隣り合わない表へ動くときは途中の表を通ります。0から4へ動くと1、2、3を通ります。途中の表では止まりません。

制御にはマイコンと、安定化した4.8Vの外部電源が要ります。信号線はデモのD9につなぎます。SG92RとマイコンのGNDをつなぎます。

## 組み立て

手順の正本は `build/assembly.json` です。同じ変換列で干渉を検査したのが `build/assembly_report.json` です。下は16工程を1工程1行に書いたものです。

1. 外装を底を下にして置きます。配線の窓がある面を奥にします。窓は11 × 7mm（上は45°の尖り屋根）で、先端の黒い3ピンコネクタ（8.2 × 4.4mmと仮定）を通せます。
2. 箱の外で、付属ホーンを長い腕を下にして `horn_coupler` のポケットへ−X側から押し込みます。腕の長さが違うので、逆向きは入りません。
3. ホーン無しで起動して90°で止めたSG92Rの出力軸を、−X側からホーンのハブへ差します。配線の自由端は背面の窓の側へ向けます。
4. 受けごとサーボを箱の上から下ろします。受けのピンが+Xの軸受けの帯に当たるので、1.8mmだけ−Xへ寄せて通します。帯の下で+Xへ戻して、取付耳を柵へ、ピンを縦溝へ落とします。
5. 押さえクリップ2個を耳の上から被せて押し込みます。脚の爪が受けの側面の窪みへ入って止まります。
6. 箱の外で、5本とも軸を7部品つないで1本にします。歯車の部品を台に置き、カム4、3、2、1、0、最後に端の部品（`shaft_j`）の順に、雄の六角スタブを次の雌穴へ差します。差し込むのは最後の2.8mm（歯車の穴は2.4mm）です。カムの番号は+X面にあります。向きは切り落とし面で1通りに決まります。
7. 軸2を鉛直に下ろして、両端の丸をU溝へ落とします。歯車は受けの半円歯車の歯へ上から入ります。
8. 軸1を、切り落とし面を真上から（+X側から見て）時計回りに56.1°回した向きでU溝の上に持ち、鉛直に下ろします。
9. 軸3を、反時計回りに55.4°回した向きで同じように下ろします。
10. 軸0を、時計回りに56.1°回した向きで下ろします。
11. 軸4を、反時計回りに55.4°回した向きで下ろします。
12. 位相合わせ治具を、5本の軸の−X端の六角へ上から被せます。
13. 治具を真上へ外します。
14. 案内板を上から下ろします。栓をU溝の壁の間へ、舌の爪を端壁の窪みへ入れます。
15. 画素25個を案内板の十字穴へ上から差します。足が溝を通ってカムの上に載り、面一で止まります。
16. ベゼルを上から被せます。25個の頭が窓へ入り、縁の爪が端壁の窪みへ嵌まります。

### 軸のつなぎ方

工程6では、台の上でまっすぐ押し込みます。押し込む力の見積りは、カムの継ぎ目で26.5N、歯車の継ぎ目で22.7Nです（上限40N）。向きは雄スタブの切り落とし面で1通りに決まります。鏡像や60°おきの回しは、雌穴の出っ張りに当たって入りません。

つないだ継ぎ目は、1つで約26Nの力がないと抜けません。軸の全長は、外装の両端のパッドの内面の間より0.4mm短いだけです。継ぎ目が開ける量は全体で0.4mmなので、入る長さは最低でも2.0mm残ります。

### 軸を落とすときの転がり

工程8〜11では、歯が隣の歯車に触れる高さから、軸が転がるように回しながら落とします。落とし始めの向き（56.1°と55.4°）は、歯が隣の歯とぶつからない向きとして計算した値です。回転なしで鉛直に落とすと、歯どうしが当たります。

### 治具で1歯のずれを確かめる

工程12で5本とも切り落とし面が上を向いていれば、治具は奥まで座ります。1歯（21.18°）ずれた軸があると、その軸の端の部品の六角部が治具の切り欠きに当たって、治具が浮きます。浮いたときは次のようにします。

1. 治具を外します。
2. 浮かせた軸を持ち上げて、歯の噛み合いを外します。
3. 切り落とし面が真上を向くように、歯を1つ戻すか進めて置き直します。
4. 治具を被せ直して、5本とも座ることを確かめます。

案内板を載せたあとは、軸を持ち上げられません。ずれの確認は工程12で済ませてください。

### サーボを寄せる量

工程4でサーボ一式を−Xへ寄せる量は1.8mmです。寄せずに真下へ下ろすと、受けのピンが帯に当たります。

### 分解

分解は逆順に行います。ベゼルの爪と案内板の爪は、壁のたわみで外します。無理に引き抜かないでください。爪の着脱力は実物で確かめます。

## 初期角度の合わせ方と動かし方

### 初期角度

SG92Rは90°で起動して組み立てます。90°は全画素が面一になる角度で、表2の角度でもあります。デモは電源投入で90°へ向かいます。

1. ホーンを付ける前に、SG92Rだけをマイコンにつなぎます。
2. デモを書き込んで起動し、90°で止めます。
3. 電源を入れたまま、ホーンを入れた受けを出力軸に差します（工程3）。

ホーンのスプラインは18°刻み（20山）でしか付け直せません。受けの半円歯車の歯は±92°の範囲にしかないので、付け方は「歯のある半円が上を向く」1通りに決まります。このとき受けの向きは、設計から最大±9°ずれます。

このずれは歯車で5本の軸すべてに同じだけ乗るので、位相補正で消せます。工程7で軸2を落とすと、歯は一番近い噛み合いに入ります。受けのずれが±9°以内なら、それが正しい歯です。合わせ方は次のとおりです。

1. 工程11まで済ませたら、工程12で治具を被せます。
2. 5本とも浮くときは、受けのずれです。シリアルモニターで `+` か `-` を送り、0.25°ずつ回しながら治具が座る位置を探します。
3. 1本だけ浮くときは、その軸が1歯ずれています（下の「治具で1歯のずれを確かめる」）。
4. 5本とも座ったら `w` を送り、補正値をEEPROMに保存します。次に起動したときも、この値が使われます。

### デモ

`demo/demo.ino` はArduinoのServoライブラリを使います。`firmware.py` が `patterns.py` と `params.py` から生成します。手で書き換えず、`firmware.py` を流し直してください。シリアルモニターは115200bpsです。

| コマンド | 動作 |
|---|---|
| `0`〜`4` | その番号の表へ動く |
| `p` | 平らから表1（dip）へ動いて、平らへ戻る |
| `b` | 平らから表3（bump）へ動いて、平らへ戻る |
| `g` | 表0から表4まで順に再生して、平らへ戻る |
| `c` | 組み立ての90°へ動く |
| `s` | 現在の指令角で止める |
| `+` / `-` | 位相補正を0.25°ずつ変え、今の表（または90°）へ動き直す。範囲は±10° |
| `z` | 位相補正を0°に戻す |
| `w` | 位相補正をEEPROMに保存する。起動時に読み込む |
| `?` | 一覧と今の位相補正を出す |

移動時間は、動く角度に比例します。表1枚分（34°）が600msで、それより短くはなりません。0から4へは136°で2.4秒です。動きは5次関数の滑らかな立ち上がりと止まりです。連続再生の停止は1.5秒です。

600msは、画素が浮かない最短0.05秒に安全率1.3を掛けた65msより十分長い値です。ステップ指令で最速に動かすと、画素がカムから浮くことがあります（`simulate_report.json`）。

### PHASE_TRIM_DEG の合わせ方

組み立てたあと、ホーンの付き方で全部の表の角度が同じ向きにずれることがあります。位相補正がそのずれを直します。全部の指令角に同じ値を足すので、表どうしの間隔は変わりません。治具で合わせた値（上の「初期角度」）を出発点にして、表の高さで仕上げます。

1. 表1（dip）を出します。中央の画素の窓からの深さを、ノギスの深さ計で測ります。`+` と `-` で、−3mmになる補正の幅を探します。
2. 表3（bump）を出します。中央の画素の高さを測ります。+3mmになる補正の幅を探します。
3. 2つの表がどちらも表どおりの高さ（±0.25mm）になる幅の中央に合わせ、`w` で保存します。

書き込み直しは要りません。コンパイル時の `PHASE_TRIM_DEG`（初期値0°）は、EEPROMに値が無いときだけ使われます。

高さが表どおりになる幅は、サーボ軸で最大±5.8°です（カム軸の停止区間±13.0°を、増速比2.235で割った値）。誤差があると、これより狭くなります。許容は±10°です。超えるときは、ホーンの付け方を確かめて組み直します。補正後の指令角は10〜170°に収まる必要があります。

Arduino Uno向けの実コンパイルは通りました（Flash 7166 / 32256 bytes、RAM 312 / 2048 bytes。`PHASE_TRIM_DEG` の±10°は通り、±11°は範囲外として止まります。`firmware_report.json`）。マイコンへの書き込みとSG92Rの通電は未実施です。

## 表を後から作る方法

表を変えるときに刷り直すのは、高さが変わった画素のカムだけです。カム25枚が全部変わる表を書けば、25枚になります。歯車、軸、画素、外装は共通で、変わりません。

1. `patterns.py` の `TABLES` に、5 × 5の高さの表を5枚書きます。`table[j][i]` で、`j` が行（前後のY）、`i` が列（左右のX）です。単位はmmです。並びはサーボ角の昇順で、`params.py` の `TABLE_THETA` に対応します。表2（90°）は全部0のままにします。
2. `py -3.11 models/tangible-pixel-cube/cams.py` を流します。作れる表なら `build/cams.json` が書かれます。作れない表は `CamError` で拒否されます。`design_check.py` でも同じ生成器が走ります。
3. 拒否されたら、隣の表との差が大きすぎる画素があります。直して2を繰り返します。
4. `model.py` を流して、カムのSTLを作り直します。刷るのは `print_cam_i_j.stl` のうち、内容が変わったものです。
5. 表に依存する検証と生成物を流し直します（下の「ビルドと検証の流し方」の `motion.py` 以降）。

生成器が拒否する条件は次のとおりです。

- 高さは−3〜+3mmです。
- 隣り合う表（サーボ角で34°。カム軸で76°）の同じ画素の高さの組は、低い方が−3mmなら高い方は+0.3mmまでです。−2mmなら+1.9mmまで、−1mm以上なら+3mmまでです。平ら（0mm）から−3mmへも+3mmへも動けます。−3mmから+3mmへは動けません。
- 端の表0と表4は、軸が一周して56°で隣り合います。この組はさらに厳しくなります。−3mmなら−2.0mmまで、−2mmなら−0.9mmまで、−1mmなら+0.3mmまで、0mmなら+1.5mmまで、+1mmなら+2.7mmまでです。端の2枚は、その画素で似た高さにしておきます。
- 表の間隔は、カム軸で26°以上です（停止区間の幅×2）。既定の表の間隔は34°です。
- 接点の横ずれが9mmを超える表も拒否されます。

エラー文の例です。

表1と表2で画素 (2,2) を−3mmと+3mmにしたとき。

```
画素 (2,2): 停止区間で高さが 0.259 mm 足りない（他の表の弧が食い込む。隣の表との角度差が足りない）。最も厳しい組: 角度差 76.0 度、高さ -3.0 と +3.0 mm（目安の必要角 88.3 度）
```

表0と表4で画素 (0,0) を−3mmと+3mmにしたとき。

```
画素 (0,0): 停止区間で高さが 1.737 mm 足りない（他の表の弧が食い込む。隣の表との角度差が足りない）。最も厳しい組: 角度差 56.0 度、高さ -3.0 と +3.0 mm（目安の必要角 88.3 度）
```

高さを3.5mmにしたとき。

```
画素 (0,0): 高さ 3.5 mm が範囲 -3..+3 の外
```

停止区間は、カムが同じ半径の弧で続く角度の幅です。既定は±13.0°です。広いほど位相の誤差に強くなりますが、隣の表との差の制約が厳しくなります。既定の表が通る最大は13.25°です（`patterns.py` の冒頭に書いてあります）。

## 計算で確かめたことと、実物でしか確かめられないこと

計算で確かめたことは次のとおりです。

- 全部品の組（68部品の2278組）を、サーボ10〜170°の1°刻み161姿勢で測った共通体積。設計した潰しリブ以外は0です（`verify_report.json`）
- 25個の画素の足の下面と、実カムの最高点。食い込みと浮きは0.001mm台で、表の高さとの誤差は0.00001mm台です
- 16工程の組み立ての経路と、逆順の分解。当たってよいのは設計した圧入とスナップだけで、ひずみは最大1.71%です（PLAの上限は2%）
- 軸の継ぎ目。引き抜き力は1つで26.5N（下限10N）、押し込む力の見積りは22.7〜26.5N（上限40N）です。滑り始めるトルクは、1本の軸の最大トルクの15.9倍（歯車の継ぎ目）と18.5倍（カムの継ぎ目。基準は3倍以上）です（`design_check.json`）
- 位相誤差の合計の最悪は11.70°で、停止区間の半幅13.0°に対して余裕は1.30°です。継ぎ目1つの遊びは±0.4°（5つで2.00°）と見込んでいます
- 画素1個ずつの上下の余裕。+3mmからさらに1.2mm、−3mmからさらに0.6mmです
- 刷る向きでの張り出し、立てた細物、肉厚、連結成分、ベッドへの接地（`print_review.json`）
- 1自由度の運動方程式でのトルク。摩擦係数0.35で停動の約18%です（`simulate_report.json`）

実物でしか確かめられないことは次のとおりです。

- 付属ホーンとSG92Rの出力軸のスプラインの嵌合と、回転の伝わり方。正本にスプラインの歯がありません
- 潰しリブの潰れ具合と、継ぎ目の回転ガタ。位相の誤差の予算は、継ぎ目1つの遊び±0.4°という仮定に立っています
- 足とカム、軸受け、案内の摩擦係数。計算は仮値0.35と0.45を使っています
- ベゼルと案内板の爪、押さえクリップの着脱力と、繰り返したときの寿命
- 取付耳の溝（耳の厚み + 片側0.25mm）にSG92Rの耳が入る固さ
- 印刷の収縮による隙間の増減と、面の粗さ
- 歯車の実際のバックラッシュ
- 電源を切ったときの画素の位置
- 軸が案内板を押し上げたときの画素の高さの変化（案内板を押し上げるまで浮いたとき0.17mm。許容0.1mmを超えます。停止時の高さの誤差としては、基準0.25mm以内に収まります）
- 配線の曲げと、コネクタの実寸（窓は11 × 7mmで、コネクタを8.2 × 4.4mmと想定しています）

実物で確かめる順番は、最終報告の「実物で確かめること」に書いてあります。
